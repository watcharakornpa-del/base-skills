# base-rough-cut — ไฟล์ดิบ → rough cut + ซับ (สำหรับ Premiere)

> สถานะ 4 พ.ย. 2026: **draft รอบ 1** · ทดสอบกับ `F:\Tiktok 031026\Footage\C1844.MP4` (คลิป Gen Z vs Gen Y ดิบ 2:24 → 1:10)
> เทียบกับที่ทีมตัดจริง (`Export\Gen Z vs Gen Y .mp4`): เลือกเทคและลำดับตรงกัน · ทีมตัดแน่นกว่า ~5 วิ

## ⛔ ถามก่อนเริ่ม
1. **ไฟล์ดิบไหน** (กล้องเดียว มีเสียงในตัว) · ถ่ายหลายกล้อง = ใช้กล้องที่เป็นมุมหลัก แล้วคนตัดต่อสลับมุมเองใน Pr
2. คลิปนี้**เรื่องอะไร / ควรจบที่ไหน** ถ้าในไฟล์มีหลายเรื่องหรือหลายเทค
3. มีซับ/สคริปต์ของทีมไหม (ใช้สะกดคำเฉพาะ)

## ขั้นตอน
1. **ตั้งโปรเจกต์ + ถอดเสียง** (ElevenLabs Scribe เวลาระดับตัวอักษร · คีย์ `~/.elevenlabs/api_key` ห้ามเปิดอ่าน)
   ```bash
   mkdir -p ~/Developer/video-use/<ชื่อ>/work ~/Developer/video-use/<ชื่อ>/renders && cd ~/Developer/video-use/<ชื่อ>
   cp -r ~/.claude/skills/base-rough-cut/scripts/. work/      # สคริปต์ + fonts/ (Anuphan Medium สำหรับซับพรีวิว)
   python -c "import pythainlp" || python -m pip install pythainlp   # ตัดคำไทยสำหรับแบ่งบรรทัดซับ
   python work/transcribe.py "<ไฟล์ดิบ>"
   python work/rough.py table          # → work/phrases.txt
   ```
2. **อ่าน `work/phrases.txt` ทั้งไฟล์** (id · เวลา · เงียบก่อนหน้า · ข้อความ · ธง F = คำเกิน · E = เสียงไอ/หัวเราะ) แล้วตัดสินใจ:
   - ช่วงคุยก่อน/หลังถ่าย ("พร้อมครับ" "โอเค" "เดี๋ยวไปแทรก") → ไม่เอา
   - **พูดซ้ำ / เทคเสีย** → เอาเทค**หลังสุด**ที่พูดจบประโยค (คนพูดมักแก้ในเทคหลัง)
   - **เทคแก้ที่ถ่ายท้ายไฟล์** ("เดี๋ยวไปตัดแทรกกลาง") → ย้ายไปแทนที่ช่วงเดิม
   - คำเกินที่ธง F ผิด (เช่น "อ๋อ" ที่เป็นการตอบรับมีความหมาย) → ใส่ใน `keep_fillers`
   - คำซ้ำ/พูดติดในประโยคที่เก็บ (เช่น "เราเรา") → `remove` ระบุ id
3. **เขียน `work/cuts.json`** แล้ว**ส่งรายการให้ผู้ใช้ดูก่อน build** (เทคเสีย = วิจารณญาณ ต้องให้คนยืนยัน):
   ```json
   {"segments": [[39, 60], [141, 162], [70, 118]],
    "remove": [[31, 31, "พูดซ้ำ เราเรา"]], "keep_fillers": [],
    "notes": ["ตัด #61–69 เทคเปิดเรื่อง 2 รอบ → ใช้เทคแก้ #141–162 แทน"], "cfg": {"max_gap": 0.4}}
   ```
   `segments` = ช่วง id ที่เก็บ **ตามลำดับที่จะเล่น** · ภายในช่วง สคริปต์ตัดเงียบเกิน `max_gap` + คำเกินธง F ให้เอง
4. **Build** `python work/rough.py build` (~3.5 นาที · รวมเรนเดอร์พรีวิวมีซับ) → `renders/preview.mp4` · `renders/roughcut.xml` · `renders/roughcut.srt` · `work/edit_report.txt`
5. **ตรวจ** — เปิด preview ฟังรอยต่อทุกจุด (คำขาด = เพิ่ม `pad_in`/`pad_out` · ยังเงียบนาน = ลด `max_gap`) · ดึงเฟรมดูว่า crop แนวตั้งเห็นคนพูดกลางจอ · อ่าน SRT ทุกบรรทัด แก้คำผิดจากการถอดเสียง
6. **ส่งเข้า Premiere** — ผู้ใช้ `File › Import` ไฟล์ `roughcut.xml` (ได้ซีเควนซ์ "Rough Cut - <ไฟล์>" แนวตั้ง 30 fps ภาพย่อ 88.89% ให้เต็มความสูง)
   แล้ว `File › Import` ไฟล์ `roughcut.srt` → ได้ไอเท็มซับใน Project panel → **ลากลงไทม์ไลน์ที่ 00:00** (Pr สร้างแทร็ก Captions ให้) · ถ้ายังไม่เห็น: เปิดตา 👁 ของแทร็ก Captions / `Window › Text` แท็บ Captions
7. คนตัดต่อเกลาต่อใน Pr (จังหวะ · สลับมุมกล้อง · ปก) → export → ใช้ base-motion-collage ใส่ B-roll

## ไฟล์ดิบเดียวมีหลายเรื่อง (เช่น ถาม-ตอบ 7 ข้อ) → แบ่งเป็นหลายคลิป
- อ่าน phrases.txt แล้วเสนอตาราง **Topic · ช่วง id · ความยาว · ตัดอะไร** ให้ผู้ใช้ยืนยันก่อน (คลิปละคำถาม+คำตอบ · ใช้เทคหลังสุด)
- เขียน `work/cuts_1.json … cuts_N.json` แล้ววนทีละคลิป: ก๊อปเป็น `cuts.json` → `build` → เปลี่ยนชื่อผลเป็น `clipN-*` (ไม่งั้นคลิปถัดไปเขียนทับ)
  · แก้ชื่อซีเควนซ์ใน XML เป็น "<ไฟล์> คลิป N" ให้ import หลายคลิปแล้วชื่อไม่ซ้ำ
- `full` (ไฟล์ 1080 สำหรับ collage) วนแบบเดียวกัน · เรนเดอร์พร้อมกันได้ 3 คลิปถ้าแยกโฟลเดอร์ `work/` ของใครของมัน (ไฟล์ดิบ 4K HLG ~10 นาที/คลิป)

## ค่าตั้ง (`cfg` ใน cuts.json)
| ค่า | เริ่มต้น | ความหมาย |
|---|---|---|
| `max_gap` | 0.40 | เงียบเกินนี้ตัดออก (ทีมตัดแน่น → ลองลด 0.30) |
| `pad_in` / `pad_out` | 0.06 / 0.14 | เผื่อก่อน/หลังคำ กันพยัญชนะต้น/เสียงท้ายขาด |
| `cap_chars` | 28 | ตัวอักษรต่อบรรทัดซับ (ทีมใช้ ~26 สูงสุด 36) |
| `seq_fps` `width` `height` | 30 · 1080 · 1920 | ซีเควนซ์ปลายทาง |

## กฎที่ห้ามพลาด
- **ไม้ยมก ๆ ต้องเว้นวรรคหน้าและหลังเสมอ** (มากๆ → มาก ๆ · จริงๆ → จริง ๆ) ทั้งในซับ, Super และ Text Hook (ผู้ใช้สั่ง) · สคริปต์แก้ในซับให้อัตโนมัติ ส่วนข้อความที่พิมพ์เองในฉากต้องเว้นเอง
  · บรรทัดซับห้ามขึ้นต้นด้วย ๆ — สคริปต์ติด ๆ กับคำก่อนหน้าให้แล้ว (เคยได้ "ยาก" | "ๆ ด้วยเหมือนกัน")
- `full` คำนวณช่วงตัดใหม่จาก `cuts.json` ทุกครั้ง (เดิมอ่าน `keep.json` ค้างจาก build ล่าสุด → ไฟล์ 1080 ทุกคลิปกลายเป็นคลิปสุดท้าย · เจอจริง C5395) · ก่อน `full` ต้องก๊อป cuts ของคลิปนั้นเป็น `cuts.json` เสมอ
- ซับต้อง**ไม่มีบรรทัดเวลากลับหัว** (จบก่อนเริ่ม) — Premiere import SRT จะหยุดอ่านตรงนั้นเงียบ ๆ (เคยได้ 3/52 บรรทัด) และ MOV ซับค้างจอ · `rough.py` ซ่อมให้แล้วและพิมพ์ ⚠️ ถ้ายังเหลือ · ก่อนส่งให้นับบรรทัดใน Pr เทียบกับ SRT
- **ไฟล์ดิบ 29.97 fps:** Premiere อ่าน `<in>/<out>` ใน XML เป็นเฟรม 30 (ไม่สน ntsc) · ถ้าเขียนเป็นเฟรม 29.97 จุดตัดจะเลื่อนเร็วขึ้น 0.1% ของเวลาไฟล์ดิบ (C5395 นาทีที่ 12 เพี้ยน 0.7 วิ → หน้าในวงกลม B-roll/ซับไม่ตรงเสียง ผู้ใช้จับได้) · `rough.py` ใช้เฟรม 30 แล้ว · ตรวจหลัง import: อ่าน InPoint ของ V1 ใน .prproj เทียบ `keep.json` ต้องต่างไม่เกิน 1 เฟรม
- **ห้ามตัดคำลงท้ายที่มีความหมาย** (อ่ะ นะ ครับ เว้ย) — FILLERS มีแค่คำเกินที่ยืนเดี่ยว ๆ
- ห้าม build แล้วส่งงานโดยไม่ให้ผู้ใช้ดูรายการเทคที่ตัด (ตัดเนื้อหาผิด = เสียเวลากว่าตัดเอง)
- ซับต้องตรวจคำทุกบรรทัด — Scribe สะกดชื่อเฉพาะ/คำอังกฤษผิดได้ ("Metafor") · ไม่ใส่ซับช่วงที่จะขึ้น B-roll ทีหลัง (ลบใน Pr)
- **กล้องทีมถ่าย HLG (HDR BT.2020)** — พรีวิวต้องแปลงเป็น Rec.709 (`rough.py` ทำให้เองเมื่อเจอ HLG/PQ) ไม่งั้นสีทึบเพี้ยน (ผู้ใช้ติมาแล้ว) · ใน Premiere ภาพปกติเพราะ Pr แปลงให้
- พรีวิวต้อง**ฝังซับ**ให้ดูด้วย สไตล์เดียวกับซับทีมใน Premiere (Anuphan Medium ขาว ไม่มีขอบ เงาบาง · อ่านจาก CaptionDataTemplateStyle ใน .prproj)
- **ห้ามฝังซับไทยด้วย ffmpeg** (`subtitles`/`drawtext`) — วางวรรณยุกต์ซ้อนผิด ("นี้" ้ จมทับ ี) ทุกฟอนต์ ผู้ใช้ติว่า "ฟอนต์จม" · `rough.py` เรนเดอร์ซับผ่าน HyperFrames (Chrome) แทน (+~2.5 นาที)
- Windows: ทุก `open()` ใส่ `encoding='utf-8'` · สคริปต์ที่พิมพ์ไทยต้อง `sys.stdout.reconfigure(encoding='utf-8')`

## ข้อจำกัดที่รู้แล้ว
1. ใช้ไฟล์ดิบได้ทีละไฟล์ (กล้องเดียว) · ยังไม่รองรับหลายกล้อง/เสียงแยกที่ซิงก์ใน Pr
2. ยังต้อง import XML/SRT เองใน Premiere (สะพาน AI Story Cutter ยังไม่มีคำสั่ง import)
3. crop แนวตั้งเป็นกลางภาพเสมอ (ไม่ตามหน้า) · คนพูดไม่อยู่กลางเฟรม → ปรับ Position ใน Pr
4. ตัดคำซ้ำ/พูดติดได้ระดับวลีของ Scribe (ไม่ถึงระดับพยางค์)
5. ต้องมี `pythainlp` สำหรับตัดบรรทัดซับ (`python -m pip install pythainlp`) · ไม่มีจะตัดกลางคำ

## เจ้าของอยากได้ความเห็นเรื่อง
1. ตัดเงียบแน่นพอไหม (ค่า `max_gap`) · รอยต่อคำขาดตรงไหน
2. เลือกเทคถูกไหม
3. ซับแบ่งบรรทัดอ่านง่ายไหม
